GLOBAL HYBRID CLOUD NETWORK & SECURE MIGRATION FABRIC
MASTER ENGINEERING JOURNAL, ERROR LOG & INTERVIEW GUIDE
======================================================================

1. EXECUTIVE SUMMARY & BUSINESS SCENARIO
----------------------------------------------------------------------
- Business Requirement: A major online sports betting platform expanding into a 
  newly regulated market needed an enterprise-grade hybrid cloud architecture.
- Architecture Challenge: 
  * Private Infrastructure: Core transactional gaming engine and compliance databases 
    hosted securely on private virtualization/storage layers.
  * Public Cloud Tier: Frontend web streaming APIs and player analytical engines 
    running on public cloud environments (AWS/Azure).
  * Hybrid Challenge: Low-latency secure connectivity, automated Infrastructure as Code (IaC), 
    disaster recovery backups, and robust perimeter firewall security.
- Zero-Cost Open-Source Strategy: Replaced expensive proprietary components (VMware vSphere, 
  Cisco ASAv, AWS paid services, Veeam) with powerful open-source equivalents (Docker, PostgreSQL, 
  Python Boto3 simulation, Ansible, local backup scripts) to build a reproducible local lab.


2. OPEN-SOURCE TECHNOLOGY MAPPING
----------------------------------------------------------------------
* VMware vSphere / ESXi        --> Linux KVM / QEMU & Docker Containerization
* vSAN / Nimble Storage        --> Local Docker Volumes & File-based Storage
* VMware NSX-T Overlay         --> Docker Bridge/Overlay Networks & Open vSwitch
* Cisco ASAv Firewall          --> Linux iptables / nftables & VyOS Routing
* AWS / Azure Infrastructure   --> LocalStack & Python-based Cloud Simulation (Boto3)
* Veeam Backup & Recovery      --> Automated Python/Tarball Encrypted Backup Vaults
* Automation & IaC             --> Ansible & Python Core Automation Scripts


3. ARCHITECTURE & COMPONENT BREAKDOWN
----------------------------------------------------------------------
A. Private Database Tier
   - PostgreSQL running in a containerized Docker environment (`private-db`).
   - Automated schema setup and table provisioning handled via Ansible playbooks (`ansible/setup_db.yml`).

B. Secure Migration Ledger Fabric
   - Python-based extraction script (`scripts/migrate_ledger.py`) pulling active player 
   - balances and transaction logs from PostgreSQL into structured JSON payloads (`migration_payload.json`).

C. Cloud Network & VPC Simulation
   - Python-based infrastructure simulation (`scripts/cloud_fabric.py`) modeling 
     cloud VPC topologies, public/private subnets, and routing rules without binary lock-in.

D. Version Control & CI/CD Pipeline
   - GitHub Actions workflow (`.github/workflows/ci.yml`) automating script validation on every push.
   - Strict `.gitignore` configurations maintaining a lightweight repository footprint.


4. COMPLETE ERROR LOG, MISTAKES & TROUBLESHOOTING GUIDE
----------------------------------------------------------------------
MISTAKE/ERROR 1: GitHub File Size Limit Rejection (GH001)
- Symptom: Running `git push -u origin main` failed with:
  `remote: error: File terraform/localstack/.terraform/providers/.../terraform-provider-aws_v5.100.0_x5 is 674.20 MB; this exceeds GitHub's file size limit of 100.00 MB`
- Root Cause: Compiled Terraform AWS provider binaries and local provider provider caches were accidentally tracked by Git during initial setup.
- Rectification / Action Plan:
  1. Removed tracking for local cache folders: `git rm -r --cached terraform/localstack/.terraform`
  2. Updated `.gitignore` to strictly exclude `.terraform/`, `*.tfstate`, and compiled binaries.
  3. Amended the previous commit (`git commit --amend`) and force-pushed a clean, lightweight codebase (`git push origin main --force`).

MISTAKE/ERROR 2: Standalone Docker Compose Binary Not Found
- Symptom: Running `docker-compose up -d` returned `Command 'docker-compose' not found`.
- Root Cause: Modern Ubuntu Linux distributions bundle Docker Compose as a native Docker CLI plugin rather than a legacy hyphenated binary (`docker-compose`).
- Rectification / Action Plan:
  - Switched command syntax to the modern standard: `docker compose up -d`.

MISTAKE/ERROR 3: Working Tree Clutter from Runtime Artifacts
- Symptom: Running `git status` showed untracked temporary JSON export payloads (`migration_payload.json`) and local state files (`terraform/terraform.tfstate`).
- Root Cause: Runtime execution outputs were not initially blocked from git tracking.
- Rectification / Action Plan:
  - Added runtime artifacts and cache directories (`migration_payload.json`, `cloud_state/`, `*.tfstate`) to `.gitignore` to ensure a permanently clean working tree.
